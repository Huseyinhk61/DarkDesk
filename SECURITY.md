# Security reporting

DarkDesk can modify real desktop files. Reports about path validation, unsafe undo, native IPC, update integrity, or credential exposure deserve particular care.

If the repository's **Security → Report a vulnerability** option is available, use it to contact the maintainer privately. Private vulnerability reporting must be enabled by the repository owner; this project does not claim that it is already enabled.

If private reporting is unavailable, open an issue asking the maintainer to establish a private contact channel. Do not include exploit details, tokens, personal file contents, or sensitive logs in a public issue.

Include the affected version and platform, a minimal reproduction using disposable files, the expected result, and the impact. No response-time or maintenance guarantee is currently defined. Use the latest available release when reproducing a problem.
